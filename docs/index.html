Designed to be cautious

Cleaning software should explain itself.

Automatic cleanup is deliberately narrow. The application does not turn “more space” into permission to sweep through personal work.

01

Safe default

Only the current user’s stale temporary files can be placed in the automatic cleanup plan. Links, protected folders, recent files and locked files are skipped.

02

Clear approvals

Manual cleanup and package-cache tasks require a confirmation phrase in the local dashboard. The system Trash / Recycle Bin opens for you to review.

03

Read-only discovery

Large documents, images, videos, duplicate candidates, repositories and possible dead code are inventories for your decision. They are never automatic deletion targets.

One honest workflow

Scan, decide, keep a receipt.

  1. 1

    Scan safe areas

    The app builds a limited plan from eligible stale temporary files. Scanning changes nothing.

  2. 2

    Review and confirm

    You see the candidate count, size and paths before the local cleanup action can run.

  3. 3

    Read the report

    Each completed cleanup, cache task or requested inventory receives a local report.

For developers, without shortcuts

Package caches are managed by their own tools.

easy-pc-cleaner can ask npm, npx, pip and uv to run their supported cache operations. Verification is the starting point. Purges are always manual, and the 90-minute scheduler never performs a full package-cache purge.
